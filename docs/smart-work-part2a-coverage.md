# Smart Work Part 2A: saved coverage setup

This deliberately small part saves approved primary/backup machine coverage, site access windows, travel/service allowances, and operator weekly work windows. All clock times are Libya local times. No defaults claim that an operator is available.

Owner/admin screen: `/settings/smart-work-coverage`, linked from operator navigation for owners/admins. No daily approval workflow is introduced. Saving a rule does not create, release or reassign an existing duty or route. No Start Trip, product selection, stock reservation, inventory movement, XY call or coordinator is included here.

Permissions: active owner/admin with a linked team member and no forced password change; checked before privileged reads and again before saves. Save actor comes from the authenticated server profile, not JSON. RPC is security-invoker and callable only by service_role; it rechecks actor role and active eligible targets against team_members. Both new tables have RLS and browser roles have no grants. Audit events are append-only for the application. Expected version prevents stale saves. No route/stock-claim operation is present or recreated from a previously blocked operation.

The migration's canonical filename is generated by Supabase CLI in the feature workflow. The prepared SQL under feature-sql must match the committed migration byte-for-byte. Isolated PostgreSQL fixtures are for CI only, never production. Production installation creates empty configuration/audit tables; it must not seed made-up coverage or work hours.

Verification: validator and real API handler tests run locally against a database double; isolated PostgreSQL workflow checks schema, version conflicts, durable saves, audit, actor eligibility and grants. Full TypeScript/build are separate checks. Authenticated production browser saves and shift-accurate day allocation are not implied by these tests.

Next small part: persistent daily duties using approved settings, retaining owners and original deadlines across individual trips and day boundaries. Atomic Start Trip and reminders remain later independent parts.

Rollback: revert this part's app code and navigation link. Leave saved settings/audit tables intact, inaccessible to browser roles; no operational-data rollback is required.
