# Part 2B: saved service duties, not dispatch

Small follow-on to Part 2A. `/operator/daily-duties` records one outstanding obligation per physical machine when verified XY observations show today/urgent/immediate priority. Original required date and deadline survive refreshes, healthier/missing readings and midnight. The deadline is the end of the first approved site-access day at/after detection; an already missed deadline stays missed. No invented deadline where coverage is missing. Urgency controls allocation order, not invented fixed-hour SLAs.

Opening/refreshing the screen invokes a server-authenticated evaluation, available to ordinary active operators without an owner-approval gate. Existing manual route owners are recognized, approved primary/backup rules fill unowned duties only when verified work budgets and access windows permit. Existing duties and other open trips consume time before new promises. Ownerless/future-dated/conflicting routes do not pretend the machine is covered today. Existing owners are never silently replaced. This release has no handover endpoint.

Duty writes are serialized in one PostgreSQL transaction and audited by revision. Browser roles cannot access the tables or refresh RPC directly. Server determines the actor; no client machine/quantity/deadline/owner/status is accepted. RLS is enabled; application audit history cannot be edited or deleted. No route or inventory write path is added and the earlier blocked route/stock claim is not recreated.

Completion requires an existing completed route stop after the duty began, its committed inventory receipt/workflow, non-offline quantity evidence, positive reviewed fill lines, and complete fresh mapped XY readings after completion with no low or empty lane. Partial/pending service stays required as verification_pending. Full readings without the service evidence are never enough. This is conservative; an old unverified manual visit may need follow-up rather than being auto-cleared.

No unattended scheduler or alerts in this part: evaluation happens when an authorized person opens or refreshes the page. No Start Trip, pickup, stock reservation/deduction, automatic wages, shift changes or live sales dependency. Saved duties are separate from existing dispatch. Keep using assigned routes to collect goods.

Release checks: isolated PostgreSQL schema replay/permissions/persistence, capacity overflow, repeated refresh, carryover, skipped/partial/offline completion, two concurrent sessions, actual handler authorization tests, full TypeScript, preview build. Production browser operation and real dispatch remain separately verified. No production fixture data or staffing rules are seeded. Rollback removes UI/API entry points; retain duty/audit history rather than deleting obligations.
